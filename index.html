Install the development source

Python 3.11 or newer is required. Matching wheels contain the Rust extension and precompiled Wasm views. Building this checkout requires Rust 1.90 or newer. Install the optional numeric runtime for the Python-callback examples below, or start with the native portable API.

git clone --branch api-native-prototype-2026-10-19 \
    https://github.com/255BITS/foldlitedb.git
cd foldlitedb
python -m pip install '.[reducers]'

The base package has no external runtime dependencies. Python ordered folds work without the numeric extra.

A metric in a few lines

The map sees a document and emits a group key plus a value. Mean() keeps the count and mean current as documents arrive. These examples start with a fresh metrics.db file.

from foldlitedb import Database, Mean, View

def measurements(document):
    yield document.payload["metric"], document.payload["value"]

metrics = View("metrics", "1", measurements, Mean())

with Database("metrics.db") as db:
    db.register(metrics)
    documents = db.add_many([
        {"metric": "loss", "value": 4},
        {"metric": "loss", "value": 8},
    ])
    result = [(row.key, row.result) for row in db.rows("metrics")]
    assert result == [("loss", {"count": 2, "value": 6.0})]

There are no required document names or positions. add_many returns the resolved documents in input order, including generated identities and source positions. Save those records outside the database if you need to regenerate it.

Append freely. Name when useful.

Use add(payload) for one JSON value. Every unnamed call appends a new document. Supply an optional unique name when identical retries should count once.

with Database("metrics.db") as db:
    db.register(metrics)
    saved = db.add({"metric": "loss", "value": 3}, id="measurement-3")
    assert db.add(saved.payload, id="measurement-3") == saved
    assert db.get("measurement-3") == saved

Documents are immutable: changing an existing name's contents raises DocumentConflict. Names are scoped to a source. For external logs, an explicit source and offset can supply the replay identity instead.

Read once, follow changes

rows handles ordinary reads with bounded snapshot pages. Use query when you also need a cursor for a change feed.

with Database("metrics.db") as db:
    db.register(metrics)
    snapshot = db.query("metrics")
    fourth = db.add({"metric": "loss", "value": 1})
    updates = db.changes("metrics", since=snapshot.cursor)
    assert updates.rows[0].result == {"count": 4, "value": 4.0}

An append commits documents, checkpoints, view states, and change records together. Snapshot pages keep one committed prefix while new documents arrive.
