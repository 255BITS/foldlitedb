Install from your checkout

Build prerequisites are Python 3.11+, Rust/Cargo 1.90+, and a platform C compiler and linker. SQLite is bundled with the extension. Run from the repository root:

python -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .
python examples/portable_metrics.py

On Windows, activate with .venv\Scripts\activate in an MSVC build environment. No Node compiler is needed for the bundled views. To build a local wheel, run python -m pip wheel . --no-deps --wheel-dir dist, then install the resulting .whl on a matching platform. Installing a built wheel needs neither Rust nor Node. PyPI release setup remains pending.

A native metric in a few lines

The bundled metrics module maps each payload's string metric and numeric value, maintaining count, sum, minimum, maximum, and mean. Start with a fresh metrics.db file:

from foldlitedb import PortableDatabase, PortableView

metrics = PortableView.bundled("metrics")
with PortableDatabase("metrics.db", metrics) as db:
    documents = db.add_many([
        {"metric": "loss", "value": 4},
        {"metric": "loss", "value": 8},
    ])
    assert list(db.rows())[0].result == {
        "count": 2, "sum": 12, "min": 4, "max": 8, "mean": 6,
    }

Rust executes both map and reduce through a bounded Wasm interpreter and commits the resulting view in SQLite. There are no Python callbacks on this path. add_many returns resolved documents, including generated IDs and source positions. Retain those records outside the derived database for replay.

Append freely. Name when useful.

Each unnamed add(payload) creates a new observation. Supply a source-scoped name when identical retries should count once. Documents are immutable; conflicting reuse raises DocumentConflict.

with PortableDatabase("metrics.db", metrics) as db:
    saved = db.add({"metric": "loss", "value": 3}, id="measurement-3")
    assert db.add(saved.payload, id="measurement-3") == saved
    documents += (saved,)

External logs can supply source and monotonically increasing position instead. Resolved Document records replay through ingest without counting twice.

Read once, follow changes

rows() follows bounded snapshot pages. Use query() when you also need a cursor for subsequent changes:

with PortableDatabase("metrics.db", metrics) as db:
    snapshot = db.query()
    fourth = db.add({"metric": "loss", "value": 1})
    updates = db.changes(since=snapshot.cursor)
    assert updates.rows[0].result["mean"] == 4
    retained = tuple(db.documents())

with PortableDatabase("rebuilt.db", metrics) as rebuilt:
    rebuilt.ingest(retained)
    assert list(rebuilt.rows())[0].result["mean"] == 4

Each batch commits documents, checkpoints, group states, and changes together. The native engine currently holds one exact module per database. A different module needs a fresh database and replay.

The same module, entirely in a browser

Open the static playground, import JSON or JSONL, and watch groups update locally. Its dedicated worker executes the same compiled module used by Python. Export documents and verify a replay before closing the page: browser storage is currently in memory.

The browser integration example includes the exact client import, resource-copy step, and a working static page. No application server is needed to process documents.

Using Python callbacks instead

The existing Database API supports trusted Python maps, ordered folds, and multiple views in a separate SQLite schema. Install python -m pip install '.[reducers]' for its numeric Rust/Wasm reducers, or use dependency-free Python OrderedFold. Source installation still builds the native extension and requires Rust. Callback maps and folds run in Python; they do not become browser view modules.

See the callback API and examples for registration, named-view reads, automatic rebuilds, and compaction.
