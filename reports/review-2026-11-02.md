**Foldlite DB engineering review — 2026-11-02**

Reviewed commit `a7d209cae165d9578cf4b73e15133a47492d4e4c` (package version `0.1.4`). Three independent subagents reviewed native durability, runtime/browser portability, and Python API/projections; the primary reviewer reviewed the architecture, CI, release configuration, and verification evidence. Existing untracked `views/assembly/sliders/` and concurrently appearing `videos/` work were excluded. This review changes no product code.

The native engine has a sound foundation: immutable inputs, computation before durable append, explicit uncertain-write recovery, and disposable caches with meaningful provenance checks. The highest risks are at the boundaries around that engine. Supported file operations can lose acknowledged documents, and the Python callback/projection subsystem does not uphold the transaction, replay, and invalidation contracts described for the native path. I would resolve the P1 findings before relying on the affected APIs for durable or correctness-sensitive workloads.

The most valuable engineering decision is to establish one explicit computation contract. README and DESIGN describe one native Wasm view per database, but the shipped public API also exports callback views, Python folds, registration, and external projection caching. Those features currently implement a second state machine with different failure and recovery behavior. Preserve the native core's small scope; either give that second subsystem a complete, separately documented contract or remove it from the supported surface. Fixing individual symptoms without settling ownership of state and progress will leave similar bugs.

Priorities below mean: **P1** requires correction before depending on the affected guarantee; **P2** is a significant integrity, compatibility, resource, or verification gap; **P3** is documentation consistency. Findings include observed behavior separately from recommended changes. File links refer to the reviewed checkout.

1. **P1 — `reset=True` bypasses exclusive ownership and can orphan acknowledged writes.**

   [database.py:260](../src/foldlitedb/database.py#L260) deletes the log, cache, and lock before acquiring native ownership or validating the view. On Linux, an existing owner retains handles to the unlinked files while the replacement obtains fresh files at the same names. Both instances continue acknowledging writes, but the old owner's documents disappear from the named database.

   Reproduced against the freshly built wheel, using a temporary `path`:

   ```python
   owner = Database(path)
   owner.add({"metric": "x", "value": 1})
   replacement = Database(path, reset=True)  # succeeds with owner still open
   owner.add({"metric": "x", "value": 2})  # acknowledged to detached log
   replacement.add({"metric": "x", "value": 3})
   owner.close()
   replacement.close()
   # Reopen: one document, sum 3. The original owner saw two documents.
   ```

   Separately, `Database(path, b"bad module", reset=True)` deletes an existing log and then raises. The current code also suppresses unlink errors, making partial resets possible.

   Move reset into the storage ownership protocol, validate prerequisites before destructive mutation, and hold a stable coordination lock throughout replacement. Reject a reset while another owner is active. Regression coverage should verify competing owners/resets and that invalid modules or failed reset operations preserve existing data. This was reproduced on Linux; Windows behavior needs its own verification.

2. **P1 — A database's cache path can be another database's authoritative log.**

   Storage accepts arbitrary primary filenames, while [storage.rs:250](../native/engine/src/storage.rs#L250) selects `<path>.cache` and [storage.rs:279](../native/engine/src/storage.rs#L279) renames a checkpoint over that destination. The actual-log inode lock does not coordinate replacement of that pathname by another database.

   ```python
   a = Database(directory / "data")
   b = Database(directory / "data.cache")
   a.add({"metric": "a", "value": 1}, id="a1")
   b.add({"metric": "b", "value": 2}, id="b1")
   a.checkpoint()  # replaces b's log with a cache file
   b.add({"metric": "b", "value": 3}, id="b2")  # still acknowledges on Linux
   b.close()
   a.close()
   Database(directory / "data.cache")  # Native log header is corrupt
   ```

   Reproduced with the current wheel: the pathname's magic changed from `FOLDLOG1` to `FOLDCAC1`, and subsequent acknowledged writes went to the detached original inode.

   Reserve and coordinate the entire primary/sidecar namespace before creating or replacing files. A dedicated database directory is one possible design; whichever layout is chosen, ordinary checkpointing must never overwrite an unrelated file or another database's source log. Test conflicting names in both opening orders and across supported platforms, including aliases and closed existing logs.

3. **P1 — Callback results depend on which append API is used, and retries double-count.**

   [database.py:406](../src/foldlitedb/database.py#L406) obtains the native insertion/replay outcome, but [database.py:412](../src/foldlitedb/database.py#L412) then maps every supplied document, including identical replays. Conversely, [database.py:378](../src/foldlitedb/database.py#L378) and [database.py:384](../src/foldlitedb/database.py#L384) bypass callback processing for `add` and `add_many`.

   ```python
   view = View(
       "totals", version="1",
       map=lambda d: [("total", d.payload["value"])],
       reducer=OrderedFold(0, lambda s, v: s + v, version="1"),
   )
   with Database(":memory:", view) as db:
       db.add({"value": 2})
       assert db.query("totals").rows == ()
       doc = Document("a", {"value": 3}, position=1)
       db.ingest([doc])  # callback state 3
       retry = db.ingest([doc])  # inserted=0, replayed=1; callback state 6
   ```

   Route all supported append APIs through one acceptance/computation pipeline. Callback computation needs the resolved, newly accepted documents rather than the original arguments. Verify equivalent results across `add`, `add_many`, `ingest`, and `ingest_many`, with new records, replays, duplicate identities within a batch, and mixtures of new and retained records.

4. **P1 — Callback failures happen after document commit, and callback state cannot recover the committed suffix.**

   Native ingestion completes at [database.py:406](../src/foldlitedb/database.py#L406), before callback mapping/reduction. [database.py:535](../src/foldlitedb/database.py#L535) restores only saved callback groups; it does not replay documents beyond their checkpoint. [database.py:654](../src/foldlitedb/database.py#L654) rebuilds only the native view. The native transaction guarantee therefore does not extend to callback views.

   Reproduction: a callback mapper raising `RuntimeError("mapper failed")` makes `ingest` raise, yet one document remains durably retained. Reopening with a valid mapper returns empty callback rows despite that retained input. A second reproduction used a reducer finalizer that raises while closing: [database.py:320](../src/foldlitedb/database.py#L320) swallows the callback checkpoint error, `close()` returns successfully, and reopening retains the document but no callback state.

   If callbacks remain supported, define their commit point and recovery semantics explicitly. Stage fallible work before committing where atomic behavior is promised; maintain checkpoint coverage and replay every accepted suffix where computation is asynchronous or independently recoverable. Surface checkpoint failures and apply synchronization to Python-owned view state. Add fault tests between document commit, callback computation, and callback checkpoint publication, plus abrupt process termination. A saved aggregate without replay coverage is insufficient.

5. **P1 — Changing a projection's descriptor clears its results but preserves its consumed watermark.**

   [database.py:540](../src/foldlitedb/database.py#L540) clears saved callback groups when the view/reducer/reference descriptor changes. Independently, [projection.py:172](../src/foldlitedb/projection.py#L172) restores the old `projection` source checkpoint and resumes after that boundary. There is no descriptor check binding the restored progress to the restored state.

   Reproduced by materializing one source document `{n: 1, value: 3}` at source generation `"one"`, target cursor/position `1`, and view/reducer version `"1"`: the result state is `3`. Repeating the same source and target with view/reducer version `"2"` returns an empty tuple. A subsequent suffix would be folded without the earlier prefix.

   Persist and validate projection progress and derived state as one descriptor-bound unit. On descriptor mismatch, reconstruct from the external source from the beginning or fail explicitly before serving results. Test changes to view version, reducer descriptor, and reference data, both with and without a new suffix.

6. **P2 — Accepted source names silently produce different native and browser results.**

   [lib.rs:764](../native/engine/src/lib.rs#L764) skips Wasm mapping for every source starting with `_`. [worker.js:100](../src/foldlitedb/portable_assets/worker.js#L100) maps all appended payloads. Both hosts accept these source names; README and DESIGN do not reserve this namespace.

   For the bundled metrics view, append `{metric: "x", value: 2}` with source `"_external"`. Native retains the document and produces no rows. The browser worker produces a row with count `1` and sum `2`. This undermines export/replay equivalence using identical view bytes.

   Specify one public source-name policy and enforce it in both hosts. If metadata needs reserved sources, distinguish internal writes from public ingestion explicitly and reject reserved public names consistently. Add cross-host export/replay fixtures covering those sources and internal metadata records.

7. **P2 — The log does not persist the frame linkage claimed by the design.**

   [DESIGN.md:37](../DESIGN.md#L37) describes hash-linked frames. [storage.rs:400](../native/engine/src/storage.rs#L400) writes magic, payload length/complement, a payload checksum, and payload. The running chain computed at [storage.rs:372](../native/engine/src/storage.rs#L372) exists in checkpoint metadata, not in subsequent log frames. A missing whole frame leaves every remaining frame's checksum valid.

   Reproduced with three separately committed values `1`, `10`, and `100`. After closing, remove the complete middle frame using the 56-byte log header and frame sizes `52 + payload_length`. Reopen succeeds, reports an invalid cache, and reconstructs two documents with sum `101`, replacing the previously acknowledged three documents/sum `111`. Source positions `[0, 2]` remain valid because gaps are supported.

   Persist a predecessor digest or equivalent contiguous frame linkage in a versioned format and test omission, reorder, and cross-log splice detection. Correct the current integrity description in any case. This finding concerns omission of otherwise unchanged frames, not authenticity against someone able to rewrite files and recompute checksums. Detecting removal of a complete final suffix additionally needs a durable trusted end boundary; a predecessor chain alone cannot prove that suffix existed.

8. **P2 — Direct `ingest` consumes unbounded iterables and snapshots mutable payloads too late.**

   [database.py:394](../src/foldlitedb/database.py#L394) eagerly calls `list(documents)` before enforcing the 1024-document batch cap or serializing payloads.

   A 5000-document generator was fully consumed before rejection. An infinite source would never reach the limit check. A generator that reused one payload dictionary while yielding values `0`, `1`, and `2` retained `[2, 2, 2]`. `add_many` and [ingest_many](../src/foldlitedb/database.py#L503) already snapshot during consumption, so this behavior is inconsistent across the API.

   Validate and snapshot each yielded document while enforcing the cap, stopping after the first excess item. Verify bounded consumption, generator exceptions without commits, and preservation of values `[0, 1, 2]` when callers reuse a mutable payload.

9. **P2 — Core checks are absent from pull-request CI triggers.**

   [.github/workflows/ci.yml:3](../.github/workflows/ci.yml#L3) runs on pushes to `master` and manual dispatch. The workflow with `pull_request` coverage, [node-checks.yml](../.github/workflows/node-checks.yml), runs the view SDK checks only. The release workflow performs substantial validation, but that is too late to provide ordinary pre-merge native/Python/browser feedback.

   Add `pull_request` to the core workflow, with stable required check names. Keep a practical PR matrix covering native Rust, an installed Python wheel at the supported minimum and a current interpreter, and actual browser parity. Run the broader platform matrix on an appropriate schedule or release gate. The repository configuration proves the trigger gap; remote branch-protection settings were not inspected.

10. **P3 — Installation and runtime documentation has drifted from the package.**

    [README.md:19](../README.md#L19) directs users to `foldlitedb==0.1.0`, while the checked package and Rust crates are `0.1.4`. [README.md:150](../README.md#L150) says Node 20+, while [views/package.json:18](../views/package.json#L18) specifies `^22.23.4 || ^24.22.1 || >=26.12.1`. DESIGN also describes a single computation path that omits the callback/projection contract discussed above.

    Align installation instructions, supported runtimes, and the actual public API with release metadata. A lightweight documentation consistency check can prevent version/runtime claims from diverging again. No external publication status was checked in this review.

Several existing engineering choices should be retained. The native [ingestion path](../native/engine/src/lib.rs#L405) computes a stage before append and publishes only after `sync_all`. Uncertain append failures poison subsequent writes and checkpoints. Storage locks both the coordination file and the actual log, and the tests cover symlink/hardlink aliases. Cache loading validates the outer checksum, module digest, database identity, verified log prefix, state invariants, and retained-document provenance. Fresh Wasm instances make explicit state meaningful, native fuel and memory bounds constrain execution, and browser worker deadlines keep runaway views away from the UI. The release pipeline builds and tests wheels and source archives. These are substantive strengths.

The next confidence investment should be invariant-driven testing around the boundaries identified here. Add a deterministic storage I/O seam for short writes, failed file syncs, failed rename/directory sync, and disk exhaustion, with crashes at each persistence boundary. Existing process-exit and synthetic torn-tail tests are useful, but they do not establish those failure outcomes. The oracle should track accepted documents and commit uncertainty, then verify recovered state, retry behavior, and unchanged acknowledged prefixes. A state-machine test spanning append, replay, checkpoint, reopen, rebuild, and module/descriptor changes would exercise combinations currently missed by isolated feature tests.

Maintain one shared native/browser conformance corpus. In addition to finding 6, targeted checks confirmed two smaller disagreements: a payload of 62 nested arrays containing `null` is accepted by native and rejected by browser ingestion because wrappers count toward depth; and a guest that relocates its output buffer into its input buffer is accepted by browser but rejected by native. [host.js:184](../src/foldlitedb/portable_assets/host.js#L184) rechecks the actual response length, while [runtime.rs:153](../native/engine/src/runtime.rs#L153) rechecks full output capacity and disjointness. No sandbox escape was demonstrated. Put these fixtures alongside numeric boundaries, structured keys, malformed modules, pagination, source names, and batch-splitting cases so both hosts implement the same ABI and data semantics.

Define a measured operating envelope before making scale claims. [Engine::open](../native/engine/src/lib.rs#L236) loads a whole checkpoint before [Disk::scan](../native/engine/src/storage.rs#L320) accumulates every decoded log batch, so warm reopen temporarily holds multiple representations of the documents in addition to cached history and indexes. The 1 GiB encoded-checkpoint limit does not bound RSS. The documented growth of retained history is an accepted limitation, not a newly discovered defect. Measure peak memory, checkpoint/close duration, cold and cached reopen, and ingestion-to-query latency across increasing document counts, key cardinalities, payload/state sizes, and batch sizes on the intended filesystem. The current benchmark records aggregate timings and storage bytes, but not peak RSS or latency distributions. Streaming verification/replay is a focused improvement to consider once those measurements identify the practical limit; compaction can remain a separately scoped project.

Recommended order of work: first fix reset and sidecar ownership, then settle and enforce callback/projection transaction and replay semantics. Next make host conformance and core PR checks mandatory, address log linkage and bounded input consumption, and add deterministic failure testing. Use measured memory and latency results to set the supported workload envelope. Each P1 should gain a regression reproducing the observed failure before its fix is considered complete.
