CouchDB-inspired views, from Python to the browser

Write a view once.
Run it in either environment.

A portable view contains both its map and its reducer. AssemblyScript compiles them into one WebAssembly module, executed by the Rust engine or a browser worker.

Try the browser playgroundUse it from Python

Development API. PortableDatabase is the native single-view engine. The existing Database API continues to support Python callbacks and multiple views. Browser view state is currently held in memory; export resolved documents before closing the page.

A native database from Python

Prebuilt wheels contain the Rust extension and compiled example modules. Installing a matching wheel needs no Rust or Node compiler. Building this source checkout requires Rust 1.90 or newer; editing AssemblyScript views also requires Node 20 or newer.

python -m pip install .
python examples/portable_metrics.py
from foldlitedb import PortableDatabase, PortableView

view = PortableView.bundled("metrics")
with PortableDatabase("portable-metrics.db", view) as db:
    documents = db.add_many([
        {"metric": "loss", "value": 4},
        {"metric": "loss", "value": 8},
    ])
    assert list(db.rows())[0].result["mean"] == 6
    snapshot = db.query()
    documents += (db.add({"metric": "loss", "value": 3}),)
    assert db.changes(since=snapshot.cursor).rows[0].result["mean"] == 5

Rust owns document identity, SQLite transactions, source checkpoints, state storage, snapshots, and changes. A bounded Wasm interpreter executes both map and reduce; Python does not execute callbacks in this path. Each database contains one view module.

A complete view in your browser

The playground is a static website. Its worker loads the exact compiled module used above, groups emitted contributions, and maintains in-memory states. No application server processes your documents. Import a JSON array or JSONL file, append measurements, export resolved source records, and rebuild the view to verify replay.

The installed package exposes the browser files through foldlitedb.portable_assets(). Copy these resources into a static website and serve them over HTTP or HTTPS. The worker client owns a deadline and terminates an unresponsive worker.

Author and build a view

Start with the example sources in views/assembly/. The SDK handles UTF-8 buffers, dynamic JSON values, validation, dispatch, and error responses. Authors implement mapping, initial state, batched updates, and finalization. Mergeable aggregations can additionally implement merge; ordered lifecycle folds preserve ingestion order.

npm ci --prefix views
npm run build --prefix views
npm test --prefix views
npm run check --prefix views

The build emits module bytes and a SHA-256 manifest into src/foldlitedb/portable_assets/. Load your compiled module with PortableView("path/to/view.wasm", sha256="expected digest"). AssemblyScript has a stricter type system than TypeScript; the example SDK exposes JSON helpers for structured documents and state.

The computation contract

OperationInputOutput
descriptorModule requestName, version, state version, ABI, merge capability
mapA batch of document payloadsAn emission array per document, including zero emissions
identityEmpty requestInitial JSON state for one group
addState and ordered contributionsUpdated JSON state
finalizeStatePublic JSON result
mergeTwo compatible statesCombined state, where declared supported

The v1 ABI accepts UTF-8 JSON through fixed buffers with a 256 KiB request and response limit. Modules have no host imports and declare at most 16 MiB of linear memory. Native execution has a fuel limit. Browser execution runs in a dedicated worker with an external timeout. Hosts retain grouping, document identity, scheduling, checkpoints, and storage.

Portable JSON numbers use IEEE-754 double precision, as in JavaScript. Python rejects integer inputs that cannot be represented exactly in that format; encode large identifiers as strings. Source positions and cursor sequences are restricted to nonnegative JavaScript-safe integers.

Retain documents; regenerate views

The module digest identifies the exact map, reducer, and state schema. Reopening a database with different module bytes fails explicitly. To upgrade a view, create a new database and replay retained documents with the new module. Resolved IDs, source positions, and ingestion order remain part of the replay contract.

with PortableDatabase("portable-rebuilt.db", view) as rebuilt:
    rebuilt.ingest(documents)
    assert list(rebuilt.rows())[0].result["mean"] == 5

Query cursors belong to their database generation and module revision. Bounded snapshot pages keep a fixed committed prefix; change pages advance from that prefix. Floating-point aggregations preserve their declared input order; arbitrary merge trees can change rounding.

For larger retained streams, iterate db.ingest_many(documents, batch_size=100). Each yielded result is a separately committed batch; choose a smaller batch size when document payloads approach the Wasm byte limit. db.documents(limit=100) exports resolved records in ingestion order at a pinned snapshot.

The in-memory browser preview also caps retained documents, groups, and change history. It reports a limit error atomically and lets you export your retained records. Persistent browser storage, history compaction, and multiple native views in one database remain future extensions.
