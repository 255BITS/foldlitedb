The Python API

PortableDatabase runs a complete Wasm map/reduce view in Rust. The existing Database API runs Python callbacks. Both expose immutable documents, atomic batches, snapshots, and changes.

PortableView and packaged assets

PortableView(module, *, sha256=None)
PortableView.bundled(name="metrics") → PortableView
portable_assets() → importlib.resources Traversable

Import these names from foldlitedb. module accepts Wasm bytes or a filesystem path. PortableView stores immutable module bytes and their sha256; an optional digest must match exactly. Module size is 1 byte through 16 MiB. Exports, imports, ABI, and descriptor are validated when the native database opens.

bundled accepts "metrics" or "catalogue" and verifies the packaged manifest digest. Metrics returns {count,sum,min,max,mean}; catalogue returns {count,items} after its ordered item fold. The portable guide describes accepted payloads. portable_assets() exposes both modules and manifests plus the buildless browser hosts. Copy its files using their resource read_bytes() methods; resources need not be ordinary filesystem paths.

PortableDatabase

PortableDatabase(path, view=None)

A Rust/SQLite database executing one complete portable view. view accepts a PortableView, Wasm bytes, or a module path. Omit it to use the bundled metrics view. path accepts a filesystem path or ":memory:". Parent directories must already exist.

Use a context manager or close(). Closing is idempotent; later operations raise DatabaseError. Reopening the same file and exact module reuses persisted state. Different module bytes fail: create a new file and replay retained documents to upgrade. Cursors bind to a database identity and exact module digest.

from foldlitedb import PortableDatabase, PortableView

with PortableDatabase(":memory:", PortableView.bundled("metrics")) as portable:
    original = portable.add({"metric": "loss", "value": 4}, id="a")
    assert portable.add(original.payload, id="a") == original
    snapshot = portable.query()
    portable.add({"metric": "loss", "value": 8})
    assert portable.changes(since=snapshot.cursor).rows[0].result["mean"] == 6
    retained = tuple(portable.documents())
    assert portable.stats()["documents"] == 2

with PortableDatabase(":memory:") as replay:
    assert replay.ingest(retained).inserted == 2
    assert replay.ingest(retained).replayed == 2

Append and replay

db.add(payload, *, id=None, source="default", position=None) → Document
db.add_many(payloads, *, source="default") → tuple[Document, ...]
db.ingest(documents) → IngestResult
db.ingest_many(documents, *, batch_size=100) → iterator[IngestResult]

add appends one finite JSON payload and returns its resolved Document(id, payload, position, source). Omitted IDs are generated; omitted positions start at zero and advance per source. An identical named add or replay at an existing source position reuses the original document. Conflicting reuse fails; previously unseen positions must advance that source's checkpoint. IDs and sources are nonempty strings of at most 4096 UTF-8 bytes. Positions range from zero through 2**53 - 1.

add_many eagerly consumes one iterable of payloads and commits atomically, returning resolved records in input order. Each member is one JSON payload, including an entire array. Empty input returns (); retrying unnamed payloads appends new records. ingest instead requires Document instances with retained identities, positions, and payloads; its result contains inserted, replayed, and sequence. Identical replay skips map execution.

ingest_many is lazy. Iterating commits separate batches of 1–1024 documents, defaulting to 100. A later error preserves previously committed batches. All atomic ingestion calls are limited to 1024 documents and 4096 map emissions. The complete map request, including its envelope and all newly inserted payloads, must fit 256 KiB; per-group add requests, states, and results must also fit their Wasm buffers. Reduce batch size for larger payloads. Map, reducer, validation, and limit errors roll back the whole current batch.

Portable JSON uses IEEE-754 double precision and at most 64 nesting levels. Python rejects integer inputs that cannot be represented exactly as a double. Encode identifiers requiring arbitrary integer precision as strings. Nonfinite numbers and invalid Unicode scalar values fail before execution.

Rows, snapshot pages, and changes

db.rows(*, key=<omitted>, limit=100) → iterator[Row]
db.query(*, key=<omitted>, limit=100, cursor=None, after=None) → Snapshot
db.changes(*, since, limit=100) → ChangePage

Portable reads omit a view name. rows lazily follows snapshot pages, pinning the committed prefix on first iteration. limit is a page size from 1 through 1024, not a total row limit. Omit key for every group or supply any JSON key, including null, for exact filtering. Rows follow canonical JSON lexical order consistent with the browser host. No transaction spans a yield to application code.

A Row contains key, reducer state, finalized result, and committed sequence. A Snapshot contains rows, cursor, after, and complete. Continue with both returned cursor and after, keeping the same key filter. New documents do not change that snapshot.

with PortableDatabase(":memory:") as portable:
    portable.add_many([
        {"metric": "a", "value": 2},
        {"metric": "b", "value": 8},
    ])
    page = portable.query(limit=1)
    snapshot_cursor = page.cursor
    rows = list(page.rows)
    while not page.complete:
        page = portable.query(limit=1, cursor=page.cursor, after=page.after)
        rows.extend(page.rows)
    assert [row.key for row in rows] == ["a", "b"]

    portable.add({"metric": "a", "value": 4})
    changes = portable.changes(since=snapshot_cursor, limit=1)
    assert changes.rows[0].result["mean"] == 3
    while not changes.complete:
        changes = portable.changes(since=changes.cursor, limit=1)

changes reads committed group postimages after a snapshot or change cursor. Pass since=0 to read retained history from the start. A page contains rows, a continuation cursor, and complete; continue with that cursor. Multiple updates to one key in a batch coalesce into one postimage. A page can split a batch's group updates. Zero-emission documents still advance progress. Cursors belong to their original database and cannot be transferred to a replayed database.

Export and inspect

db.documents(*, limit=100) → iterator[Document]
db.stats() → dict
db.close()

documents exports resolved source records in original ingestion order at a fixed snapshot, pinned on first iteration. Its page size is 1–1024. Retain these records outside the derived cache and feed them to ingest or ingest_many for replay.

stats returns documents (count), sequence, cursor, module_sha256, descriptor, and checkpoints (source-to-position mapping). Engine sequence includes document and group-state records, so it is not a document count. Snapshot and sequence values can differ when replay uses different batch boundaries.

The native engine uses SQLite WAL with full synchronous commits and a five-second busy timeout. Separate connections coordinate writes through SQLite; calls on a native engine are serialized. Retained documents and view history grow on disk. This API currently exposes no compaction, callback registration, reset, or in-place module rebuild.

Database: Python callbacks

Database(path, *, generation="default", reset=False,
         max_batch=1024, max_batch_bytes=8 * 1024 * 1024,
         max_value_bytes=1024 * 1024, max_key_bytes=4096,
         max_page_bytes=8 * 1024 * 1024,
         max_emissions_per_document=1024, timeout=30)

A local SQLite view cache, safe to share between Python threads. Separate instances and processes serialize writes through SQLite. Use a context manager or call close().

generation identifies the source collection. A conflicting generation requires an explicit reset=True, which discards derived storage and invalidates existing instances and cursors. Retain authoritative documents before resetting.

Adding documents

add

db.add(payload, *, id=None, source="default", position=None) → Document

Append any finite JSON value. Omitted IDs are generated; omitted positions start at zero or follow the source checkpoint. The returned payload is a separate JSON value, isolated from caller and mapper mutations.

An identical named retry reuses its original position. A source and position can also identify an identical unnamed retry. Conflicting identity reuse raises DocumentConflict; a new document behind its source checkpoint raises SourceOrderError.

add_many

db.add_many(payloads, *, source="default") → tuple[Document, ...]

Eagerly consume one bounded iterable of JSON payloads and append it atomically. Every member is one payload, so an array is kept whole. Results preserve input order and have generated IDs and consecutive source positions. Empty input returns ().

Input errors, map failures, limits, and position exhaustion roll back the entire batch. Retrying this unnamed call adds another batch. Replay retained documents with ingest.

Explicit documents and batches

Document(id, payload, position, source="default")
db.ingest(documents) → IngestResult
db.ingest_many(documents, *, batch_size=None) → iterator[IngestResult]

ingest atomically commits a bounded batch of explicit Document records. Identical replay performs no map work and must match the ID, position, and payload. Its result has inserted, replayed, and the committed ingestion sequence.

ingest_many is lazy: iteration commits separate bounded batches. The default batch size is max_batch; a failure preserves previously committed batches.

Views and reducers

View(name, version, map, reducer, references={})
db.register(view) → revision

A map receives a Document and yields zero or more (key, contribution) pairs. Keys and values may be structured finite JSON. Each key owns a reducer state. The view version identifies map behavior; references declares captured external-input versions.

Register callbacks on every instance that reads their views. Registration reuses compatible persisted state or rebuilds a changed definition atomically. Query and change reads catch registered callbacks up after another connection ingests documents.

Numeric reducers

Mean(*, runtime=None, positioned=False)
Sum(*, runtime=None, positioned=False)
Count(*, runtime=None, positioned=False)
Envelope(*, runtime=None, positioned=False)
RustReducer(name, *, runtime=None, positioned=False)

Install the callback numeric runtime from your checkout with python -m pip install '.[reducers]'. The source build requires Rust; installing a matching wheel does not.

The named constructors use the same descriptors and state formats as their explicit reducer IDs. They load the optional runtime when computation needs it. Ordinary maps emit finite numbers or null; null contributes nothing.

ConstructorReducer IDResult
Mean()mean/v1{"count": n, "value": mean}; empty value is null.

Count()count/v1Count and count value; counts non-null numeric emissions.

Map a document to 1 to count it. Envelope order uses source positions plus deterministic identity/emission tie breaking. positioned=True accepts explicitly positioned portable contributions; it is intended for adapters that already own that position schema.

OrderedFold

OrderedFold(initial, step, *, version, finalize=None)

A trusted Python fold for structured state. step(state, contribution) returns the next finite JSON state. Steps run in persisted ingestion order within a key. Ordered folds do not declare arbitrary partial-state merging.

from foldlitedb import Database, OrderedFold, View

def statuses(document):
    yield document.payload["record"], document.payload["status"]

status = View("status", "1", statuses,
              OrderedFold(None, lambda previous, value: value, version="1"))
with Database(":memory:") as db:
    db.register(status)
    db.add_many([
        {"record": "a", "status": "open"},
        {"record": "a", "status": "closed"},
    ])
    assert list(db.rows("status"))[0].result == "closed"

Rows, snapshots, and changes

rows

db.rows(name, *, key=<omitted>, limit=100) → iterator[Row]

Lazily iterate a stable snapshot in bounded pages. The first iteration selects its committed prefix. limit controls page size, from 1 to 4096; it does not cap total results. No transaction or lock spans a yield to application code.

Omit key for every group. Supplying any JSON key, including null, filters exactly. Keys follow canonical JSON lexical order. View rebuilds and compaction can expire a paused iterator.

query

db.query(name, *, key=<omitted>, limit=100, after=None, cursor=None) → Snapshot

A snapshot contains rows, cursor, after, and complete. Continue pages with both the original cursor and the returned after. Each Row contains key, finalized result, reducer state, and ingestion sequence.

changes

db.changes(name, *, since, limit=100) → ChangePage

Read committed key postimages after a snapshot or change cursor. A change page has rows, a continuation cursor, and complete. Continue using that page's cursor.

Changes coalesce repeated updates to the same key within one transaction. A page can split a transaction; its cursor retains per-key progress. Empty maps still advance progress.

Lookup and maintenance

get(identifier, *, source="default") → Document | None
Read a cached immutable document with a freshly decoded payload.
checkpoint(source="default") → int | None
Read the highest committed source position.
refresh(name)
Explicitly catch a registered view up to retained documents. Ordinary reads do this automatically.
compact(name, *, before)
Discard older change history while preserving the chosen snapshot boundary. The caller owns reader retention.
stats()
Return document, source, view, state, history counts and current ingestion sequence.

Errors

For the portable API, validation and Wasm failures raise DatabaseError; conflicting replay, source ordering, and invalid cursors use DocumentConflict, SourceOrderError, and CursorExpired where identified. A missing native extension raises an actionable RuntimeError.

DatabaseError extends ValueError. Its specialized errors are DocumentConflict, SourceOrderError, CursorExpired, and GenerationMismatch. Failing callbacks propagate their exceptions and roll back their transaction. Missing numeric runtime support raises an actionable RuntimeError.
